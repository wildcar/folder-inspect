## A. Уточнение задачи

Исходная формулировка: «проверка хранилища файлов на наличие очень больших файлов,
архивов, мусорных файлов, дублирующихся файлов; цель — почистить репозитории от ненужных файлов».

### A1. Что именно сканируем
- (a) обычные папки на локальном диске (проекты, документы, загрузки)
- (b) git-репозитории — рабочие копии
- (c) git-репозитории, включая историю
- (d) сетевые шары / NAS / внешние диски
- (e) несколько корней за один запуск

**Ответ (2026-09-15):** любые папки на диске. Это **проектные репозитории** — хранилища документов по
проектам внедрения (код там редко). С git не связано вообще; на git не ориентироваться и не завязываться.
Несколько корней и сетевые пути — поддерживаем как обычные папки.

### A2. Объёмы
**Ответ:** десятки тысяч файлов.

### A3. Целевые ОС
**Ответ:** Windows + Linux.

### A4. Кто пользователь
**Ответ:** не уточнялось; принято умолчание — владелец + коллеги (не обязательно разработчики), отсюда
требование «нормального интерфейса» в A11.

### A5. Режим использования
**Ответ:** вручную, по необходимости.

### A6. «Очень большие файлы»
**Ответ:** нужны **градации по типу файла**, порог для каждой настраивается:
- вообще большие файлы (записи видеовстреч, дистрибутивы) — больше 100 МБ;
- файлы, которые не должны быть большими: doc/ppt больше 15 МБ, картинки больше 5 МБ.

❓ Уточнить: таблицы xls/xlsx — тот же порог 15 МБ? PDF — предлагаю 30 МБ. Топ-N самых больших файлов и
папок — показываем всегда (умолчание).

### A7. Архивы
**Ответ:** архив определяется **по расширению**. Проектный репозиторий должен содержать файлы в прямом
доступе — открывающиеся по ссылке. Архив — признак дистрибутива, попытки сохранить старые версии или
объединить файлы для отправки; их быть не должно. docx и подобные контейнеры — не архивы.

❓ Предложение: отдельно показывать **дистрибутивы/установщики** (exe, msi, deb, rpm, dmg, pkg) как
соседнюю категорию. Включить по умолчанию?

### A8. «Мусорные» файлы
**Ответ:** bak, .DS_Store, Thumbs.db и подобное. Принятый список по умолчанию: `*.bak *.tmp *.temp *.old
*.orig *.swp`, файлы блокировок Office `~$*`, `Thumbs.db`, `desktop.ini`, `.DS_Store`, `._*`,
недокачанные `*.crdownload *.part`; плюс пустые папки и файлы нулевого размера. Список расширяется в
конфиге. Учёт `.gitignore` — снят (нет git).

### A9. Дубликаты
**Ответ:** точные дубликаты — по содержимому. Похожие имена — надо подумать; есть паттерн
«Копия … .docx». Принято: похожие имена показываем **отдельно, как кандидатов**, без автоматических
действий. Стартовый список паттернов: `Копия <имя>`, `<имя> - копия`, `<имя> - копия (N)`, `Copy of <имя>`,
`<имя> (N)`, `<имя>_v2/_final/_старый/_old`, `<имя> (Восстановлен)`.

❓ Дополнить список паттернами из практики. ❓ Какой файл в группе дубликатов считать «главным»:
самый старый по дате изменения (умолчание), самый короткий путь, или выбор вручную в интерфейсе?

### A10. Действия над найденным
**Ответ:** отчёт **и чистка**: карантинная папка с возможностью откатить + замена дубликатов на ссылки.
Прямого удаления нет; по умолчанию инструмент ничего не меняет, любые действия — через план и `apply`.

❓ Ссылки: предлагаю **hardlink** (прозрачен для пользователей и программ, не требует прав администратора
на Windows). Особенность: правка одной «копии» меняет все — приемлемо? Hardlink работает только в пределах
одного тома; если том или сетевая шара не поддерживает — группа остаётся только в отчёте.
❓ Где держать карантин: `<корень>/.folder-inspect/quarantine` (умолчание) или отдельная папка вне корня?

### A11. Формат отчёта
**Ответ:** нужен нормальный интерфейс и возможность выгрузки.

Принято (см. ADR-0001): результат сканирования сохраняется в файл `report.json` — это и есть «JSON-вывод»:
машиночитаемый снимок всех находок, из которого строятся все представления. Пользователю его читать не нужно.
Поверх него: краткая сводка в консоли, **веб-интерфейс на localhost** (открывается в браузере, встроен в
тот же exe, без установки и без интернета) с фильтрами, группами дубликатов и галочками для плана действий,
и выгрузка в **CSV, XLSX, HTML**.

❓ Подтвердить: интерфейс в браузере подходит как «нормальный интерфейс»? Альтернатива — отдельное
десктопное окно, но это заметно тяжелее в Go.

### A12. Исключения и безопасность
**Ответ:** не уточнялось; принято умолчание — исключения через конфиг `.folder-inspect.yml` в корне и флаги;
по симлинкам/junction не ходим; системные папки и собственную карантинную папку не трогаем.
